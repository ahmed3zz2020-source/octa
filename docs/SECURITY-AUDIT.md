## 🔴 الخطورة الحقيقية — المرتبة

### ⛔ حرجة — لازم تتصلّح

**١ — ٢٨٥ سهم بكل الدرجات مكشوفة**
`final_score` · `decision` · `technical_score` · `fund_score` · `risk_score_detailed` · `fair_value` · `price_target_high/low/median`

ده **منتج OCTA كله** — مكشوف لحد. أي حد يعرف يقرا الـJSON.
**السبب الجذري:** `_HIDDEN_KEYS` في `update_prices.py:154` بيخفي `weights` و`strategies` — بس **مش** `final_score` ولا `decision`.

**٢ — XSS في الأخبار**
`octa-core.js:1970-1973` و `2299-2302` — إدراج `${n.title}` و `${n.link}` **بدون `esc()`**.
الدالة `esc()` موجودة في `octa-app.js:32` بس **`octa-core.js` بيستخدمها صفر مرات**.
**التأثير:** أي سكربت خارجي بيكتب في عنوان خبر يقدر يقرا التوكن من `localStorage` ويدخل بحساب أي مستخدم.

**٣ — البوابة بتفتح قبل ما تتحقق**
`octa-gate.js:1935` — الكود مكتوب فيه تعليق «شك = مقفول» بس **السلوك معاكس**:
```javascript
try { var g0 = gateEl(); if (g0) g0.remove(); } catch (e) { }
document.body.style.overflow = '';
// ↓ بعدين بيتم الـfetch
```
لو الشبكة بطيئة أو محجوبة، الموقع بيفتح بالكامل والبوابة مش بترجع.

### 🔴 عالية

**٤ — `data_markets.js` مكشوف (٣.٤ ميجا)**
عبر `octashares.com/data/data_markets.js` — ٢٠٠ بدون أي توكن.
فيه `decision` · `conf` · `why` · `tvRec` · `score` لكل سهم + ١٠٥ حقل.
**الوزن والوصفة مش فيه** (كويس) — بس التوصية والسبب مكشوفين.

**٥ — الأوزان مكشوفة في `octa-config.js`**
`engineWeights` و `usScan` موجودين في السكربت اللي بيتحمّل في المتصفح.
`after_request` بيخفي الأوزان من **ردود الباك JSON** — بس `octa-config.js` **ملف ثابت** مش JSON.
**ده تناقض مباشر مع القاعدة اللي اتفقنا عليها.**

## 🟠 متوسطة — مهمة بس مش حرجة

**٦ — PIN ٤ أرقام (١٠٬٠٠٠ احتمال)**
الباك عنده rate limiting شغّال: `PIN_LOCK_FIRST=30` · `PIN_WINDOW_FAILS=4` · قفل ٦ ساعات.
**يعني الحماية موجودة — بس ١٠٬٠٠٠ احتمال ضعيف لو حد صبور.**

**٧ — «نسيت الباسورد» بتقول «محاولات كتيرة»**
`octa-gate.js:1348` — المستخدم ما غلطش أصلاً، بيقابل رسالة بتقوله «بعد ٣ محاولات غلط».
**مش كدب — دا إحباط.** المستخدم الجديد ممكن يفتكر في حد بيخترق حسابه.

**٨ — ٤٠٩ «الإيميل موجود» مش معالَج**
`signup()` بيتعامل مع ٤٢٩ بس، و٤٠٩ بيروح في رسمة عامة.
النتيجة: مستخدم عنده حساب بيدوس «حساب جديد» → يقوله «مقدرناش نبعت الكود».
**ما يعرفش إن عنده حساب.**

**٩ — التوكن قابل للقراءة بـXSS**
`localStorage` — مفيش HttpOnly cookie.
**متصل بالنقطة ٢ — لو اتصلّح XSS، النقطة دي قلّت خطورتها.**

**١٠ — `PIN_TRIES=5` بس الرسالة تقول «من ٤»**
`octa-gate.js:17` و `28` — رقمان مختلفين، الرسالة مكتوبة بالثابت.

## ❓ قرار محتاج منك

**الحجب الكامل (المرحلة ١) هيخلي الموقع محتاج تسجيل دخول لكل حاجة.**

ده معناه:
زائر جديد = ٣ شاشات قبل ما يشوف أي حاجة
المستخدم الحالي = لازم يسجّل دخول تاني
زيارتك إنت = نفس الحاجة

**عشان كده عندي ٣ اختيارات:**

**🅰️** نعملها كده — أقوى حماية، بس أثر أكبر على التجربة
**🅱️** نعملها تدريجي — نحمي الحسابات أول (portfolio · alerts · personalized)، وبعدين الـ7 أيام دي نطلب تسجيل الدخول بس من الزائر الجديد (مش من القارئ)
**🅲️** نأجل المرحلة ١ — نصلّح XSS والبوابة بس (ساعتين)، والحجب الكامل لما يكون في زوار حقيقيين يستاهلوا الفلوس

**أنصح بـ 🅲️** — لأن في ٥ مستخدمين بس دلوقتي، والـXSS هو الخطر الحقيقي، مش الحجب.

**قولّي رأيك.**

## ✅ النقطة ٦ — Cross-Account Takeover — اتصلحت (٢٤ أكتوبر ٢٠٢٦)

### المشكلة
```
POST /api/auth/pin/login كان بيبحث بالـPIN بس (_pin_find_by_index)
⇒ أي حد يعرف الرقم الرباعي (١٠ آلاف احتمال) يدخل حساب أي حد
⇒ ومافيش تحقق من الإيميل ولا من الجهاز
```

### الحل
| الطبقة | التغيير |
|---|---|
| الواجهة | `post('/api/auth/pin/login', { pin: p, device: bioSecret() })` |
| الباك | جهاز مش مسجّل على الحساب ⇒ `401` + `why: new_device` + `need_code: true` |
| الباك | `device` ناقص ⇒ اترفض (يمنع绕过 من clients قديمة) |
| الباك | `signup/newpin` + `challenge/newpin` ⇒ يسجّلوا `bio_hash` |
| الواجهة | `needCode()` بيعرف `new_device` + رسالة «دخول من جهاز جديد» |

### الفكرة
```
الرقم الرباعي = aid تذكره (مش سر)
الملكية      = prove بالإيميل أو بالجهاز المسجّل
```

### 🐛 bug اتصلح جنباً
```
_pin_locked_resp و _rate_check كانوا بيعملوا resp.status_code = 429
على Response immutable ⇒ Flask بيرجّع 500 بدل 429.
الحل: بناء Response(status=429) من الأول + هيدر Retry-After.
```

### الاختبار
```
① الجهاز المسجّل   → 200 (دخل)
② ⭐ جهاز جديد      → 401 new_device (طلب كود)
③ بلا device        → 401
④ PIN غلط          → 401
```

### ⭐ إضافة: سجل الدخول (٢٤ أكتوبر ٢٠٢٦)
```
قبل: last_login بس (آخر مرة) ⇒ مافيش تاريخ ولا طريقة ولا جهاز.
بعد: login_log (آخر ٥٠) + login_count لكل مستخدم:
  t = الوقت · via = pin|signup|challenge · dev = بصمة الجهاز
  ip = العنوان · newdev = جهاز مش مسجّل (اتطلب كود)
```
