# ⭐ خطة الـDurable Object لإبطال الجلسات (اتساق قوي)

> **الجولة:** ٢٢ (R22) · **الحالة:** كود جاهز ⭐ **ومتعمل** محلياً ⭐ — ⛔ **مافيش نشر** ⭐ ⛔ **مافيش مورد اتعمل** ⭐
> **الملفات:** `mgmt/worker.js` · `mgmt/wrangler.jsonc` · `assets/tests/r21-do-strong-revocation.test.js` · ٤ ملفات اختبار (سطر محمّل واحد ⭐)
> **القرار المطلوب من المالك:** مراجعة السطور ⇒ **نشر واحد** (أو إنكار ⇒ مافيش حاجة تتعمل ⭐).

---

## ① المشكلة — القيد الموثّق (مش عيب كود ⭐)

| الجولة | مصدر الإبطال | الاتساق | النتيجة |
|---|---|---|---|
| R18-A01 | ذاكرة الـWorker | ⛔ نسخة واحدة | كوكي منسوخ ⇒ يفضل شغال ٣٠ يوم ⭐ |
| R20 | **KV** (`REVOKE_KV`) | ⛔ **متأخر** (حتى ~٦٠ ثانية ⭐) | ⇒ **نافذة**: بعد الخروج، نسخة تانية ممكن تقبل جلسة اتبطلت ⭐ |
| **R22 (ده)** | **Durable Object** (`REVOKE_DO`) | ⭐ **قوي** (قراءة بعد كتابة ⇒ جديد) | ⇒ **مافيش نافذة** ⭐ |

📌 ليه الـKV مش كافي؟ ⛔ القراءة القديمة **ما بتفرّقش** بين «الجلسة مش مبطلة» و«الإبطال لسه ما وصلش» ⭐
⇒ الحل لازم يكون **مصدر واحد strongly-consistent** ⭐.

📌 الأثر: عمر الجلسة **٨ ساعات** ⭐ ⇒ نافذة الـ٦٠ ثانية مش «مشكلة-theory» ⭐ — هي نافذة **حقيقية** ⭐.

---

## ② الـDO بيعمل إيه بالظبط ⭐

**الفكرة:** صنف واحد `RevokeDO` ⇒ **instance واحد لكل `id`** ⭐ ⇒ كل الطلبات لنفس
الجلسة بتترتّب ⇒ ⛔ مافيش سباق ⭐ ⛔ **مافيش نافذة انتشار** ⭐.

- الـworker بيكلّم الـDO عن طريق binding مساحة الأسماء `REVOKE_DO` ⭐.
- **اسم الـinstance** = `rev:` + هاش **موقّع** (HMAC-SHA256) للكوكي الخام ⭐
  ⇒ ⛔ الكوكي نفسه (bearer token) **مش بيتكتب** في أي اسم ⭐.
- المسارات جوه الـDO ⭐:

| الطلب | الأثر |
|---|---|
| `POST /revoke` | ⭐ يسجّل **شاهدة الإبطال** (كتابة متزامنة ⭐) |
| `GET /check` | ⭐ بيرجّع `{"revoked": true\|false}` ⭐ |
| `POST /clear` | ⭐ يمسح الشاهدة (تنظيف ⭐ — اختياري ⭐) |

- ⭐ `state.storage` (SQLite-backed ⭐) هو التخزين ⇒ الشاهدة **تفضل موجودة** حتى لو
  الـinstance اتقفل ⭐ (وكاش في الذاكرة للسرعة ⭐).
- ⭐ **أسلوب كلاسيكي** (`constructor(state, env)` ⭐) من غير `import` ⭐
  ⇒ نفس أسلوب تحميل اختبارات المشروع بيشتغل زي ما هو ⭐.
- ⭐ **تصدير مُسمّى** (`export { RevokeDO };` ⭐ — شرط Cloudflare ⭐) موجود في
  `mgmt/worker.js` ⭐ (بجوار `export default` ⭐).

## ④ إيه اللي المالك لازم يعمله بالظبط ⭐

⛔ **مافيش حاجة تتعمل يدوي** ⭐ — الـ`migrations` بتعمل صنف الـDO **تلقائياً**
أول نشر ⭐ (الـDO **مش محتاج** namespace ID ⭐).

**① راجع** السطور دي في `mgmt/wrangler.jsonc` ⭐ (موجودة فعلاً ⭐):

```jsonc
  "durable_objects": {
    "bindings": [
      { "name": "REVOKE_DO", "class_name": "RevokeDO" }
    ]
  },
  "migrations": [
    { "tag": "v1", "new_sqlite_classes": ["RevokeDO"] }
  ],
```

> ⚠️ **`new_sqlite_classes`** مش `new_classes` ⭐ — لأن الـkey-value backend
> **مش متاح** غير على خطة Paid ⭐، والـSQLite هو المدعوم على الخطة المجانية ⭐.

**② انشر** (أوخلّي حد ينشر ⭐) — من جوه `mgmt/` ⭐:

```bash
cd octa-mgmt
npx wrangler deploy --config wrangler.jsonc
```

> ⛔ **قانون المشروع:** مافيش نشر من غير موافقة صريحة ⭐
> (`«ارفع على الدومين» ⭐) — وعمدة الدومين **مالوش** علاقة بالـworker ده ⭐
> (ده `octa-mgmt` ⭐ — مش `octa` ⭐).
> ⚠️ انتبه: `npx wrangler deploy --config wrangler.jsonc` **من جوه مجلد `mgmt/`** ⭐
> (مش الأمر العام للمشروع ⭐ — وده غيره ⭐).

**③ اتأكد** بعد النشر ⭐:

```bash
curl -s https://octa-mgmt.ahmed3zz2020.workers.dev/api/health
# المتوقّع: {"ok":true,...,"revoke_shared":true,"revoke_strong":true}
```

⇒ `revoke_strong: true` ⭐ = الإبطال بقى **باتساق قوي** ⭐ (مش KV ⭐).

### 💰 وضع التسعير ⭐ (مرجع: صفحة أسعار Durable Objects — آخر تحديث ١٣ نوفمبر ٢٠٢٦ ⭐)

| البند | Workers Free ⭐ | Workers Paid ⭐ |
|---|---|---|
| Requests | **100,000 / يوم** ⭐ | 1 مليون / شهر + ‎$0.15‎ / مليون ⭐ |
| Duration (زمن التشغيل) | **13,000 GB-s / يوم** ⭐ | 400,000 GB-s / شهر + ‎$12.50‎ / مليون GB-s ⭐ |
| SQL rows read | **50 مليون / يوم** ⭐ | أول 25 مليار / شهر + ‎$0.001‎ / مليون ⭐ |
| SQL rows written | **100,000 / يوم** ⭐ | أول 50 مليون / شهر + ‎$1.00‎ / مليون ⭐ |
| SQL stored data | **5 GB** ⭐ | 5 GB-شهر + ‎$0.20‎ / GB-شهر ⭐ |

📌 **ليه التكلفة صفر عملياً ⭐:** لوحة الأدمن ليها **مستخدم واحد** ⭐ (الأدمن ⭐)
⇒ الطلبات على الـDO = طلب واحد لكل فحص جلسة ⭐ (أقل من عشرات في اليوم ⭐)
⇒ داخل الحد المجاني بوضوح ⭐ ⇒ **$0** ⭐.

📌 **مهم ⭐:** على الخطة المجانية، لو الحد اتعدّى ⇒ Cloudflare **بتفشل العملية**
(مش بتحسبها ⭐) ⇒ ⭐ وده **fail-closed** ✅ لأن كودنا بيرفض الجلسة ⭐
(شوف §⑦ ⭐) — يعني حتى في أسوأ الأحوال **مافيش قبول صامت** ⭐.

## ⑥ إزاي بيشتغل الفحص ⭐ (ترتيب الحكم ⭐)

```
طلب فيه كوكي جلسة
   ↓
① إبطال في ذاكرة نفس النسخة؟      ⇒ رفض ⭐
   ↓ (لأ)
② لو REVOKE_DO مربوط:
     DO قال "مُبطلة"؟              ⇒ رفض ⭐ (بلا انتظار ⭐)
     DO أخطأ / رجّع رد مش مفهوم؟    ⇒ رفض ⭐ (fail-closed ⭐)
     DO قال "مش مُبطلة"؟            ⇒ ⭐ نكمّل ⭐
        └ witness الـKV (لو مربوط)؟ ⇒ "مُبطلة" ⇒ رفض ⭐
                                      ⇒ خطأ ⇒ رفض ⭐ (fail-closed ⭐)
   ↓
③ لو REVOKE_KV مربوط (من غير DO ⭐): نفس المنطق ⭐ (fallback ⭐)
   ↓
④ التحقق من التوقيع + تاريخ الانتهاء ⇒ 200 ⭐
```

📌 **قراءة التأكيد (read-after-write ⭐):** بعد `POST /revoke` بيعمل الـworker
`GET /check` ⭐ ⇒ لو الرد مش "مُبطلة" ⇒ ⛔ مافيش دليل ⇒ الكتابة بتعتبر **فاشلة** ⭐
⇒ الشاهد في الـKV بيمنع القبول الصامت ⭐.

## ⑦ سلوك **fail-closed** ⭐ (المبدأ: «مافيش دليل ⇒ مافيش ثقة» ⭐)

| الحالة | النتيجة ⭐ |
|---|---|
| الـDO مش مربوط ⭐ | ⭐ يرجع للـKV ⭐ (نافذة الـ~٦٠ ثانية الموثّقة ⭐) |
| الـDO **مش شغّال** (استثناء ⭐ / 500 ⭐ / رد مش مفهوم ⭐) | ⛔ **الجلسة تُرفض (401)** ⭐ — **مش 200 أبداً** ⭐ |
| الـDO قال "مش مُبطلة" بس الـKV فيه شاهدة ⭐ | ⛔ **تُرفض** ⭐ (الشاهد الاحتياطي ⭐) |
| الـDO قال "مش مُبطلة" والـKV **واقف** ⭐ | ⛔ **تُرفض** ⭐ (مافيش دليل ⇒ مافيش ثقة ⭐) |
| الـKV واقف (من غير DO ⭐) | ⛔ **تُرفض** ⭐ (نفس سلوك الجولة ٢١ ⭐) |
| كتابة الإبطال في الـDO **فشلت** ⭐ | ⭐ الشاهدة بتروح للـKV ⭐ ⇒ تظل مرفوضة ⭐ (مافيش قبول صامت ⭐) |
| الإبطال اتأكد بالقراءة (read-after-write ⭐) | ⭐ الحكم **مش** نهائي ⭐ ⇒ بعده توقيع ⭐ + تاريخ انتهاء ⭐ |

📌 **ملاحظة مهمة ⭐:** الـKV كـ«شاهد احتياطي» بيقدر **يرفض** ⭐ بس
**ما بيقدرش يقبل** ⭐ ⇒ الاتساق القوي للـDO **مش بيتأثر** ⭐.

## ⑧ الإلغاء (rollback ⭐) — لو المالك ما عجبهوش

1. **احذف** الكتلتين `durable_objects` + `migrations` من `mgmt/wrangler.jsonc` ⭐.
2. **انشر** ⭐ ⇒ الـworker بيرجع للـKV ⭐ تلقائياً ⭐ (الكود بيفحص
   `env.REVOKE_DO` ⇒ لو مش موجود ⇒ مسار الـKV ⭐ ⇒ **مافيش rollback للكود** ⭐).
3. ⛔ النتيجة: **الرجوع لنافذة الـ~٦٠ ثانية** الموثّقة في §① ⭐
   (يعني: نرجوع لسلوك الجولة ٢٠ ⭐ — **مش** لسلوك ما قبل R20 ⭐).
4. 📌 صنف الـDO **يفضل موجود** في الحساب (لا ضرر ⭐ — مافيش طلب ⇒ مافيش تكلفة ⭐).
   حذفه من الداشبورد **اختياري** ⭐.

> 📌 **ملاحظة ⭐:** بعد الإلغاء، ملف `mgmt/worker.js` لسه فيه صنف `RevokeDO`
> (مش متستخدم ⭐) — ينفع تسيبه ⭐ أو تشيله ⭐ (لا فرق في السلوك ⭐).
> ⚠️ لو شِلته ⭐ ⇒ شيل كمان سطر `export { RevokeDO };` ⭐ وسطر التحميل
> في ملفات الاختبار الأربعة ⭐ (وإلا الـparser هيرفض الملف ⭐).
