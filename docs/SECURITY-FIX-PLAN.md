# 🔧 خطة إصلاح الثغرات — octashares.com
> التاريخ: ٢٠ أكتوبر ٢٠٢٦
> المبدأ: **نحمي كل حاجة + المستخدم مخدعش**
> الحالة: خطة — مفيش حاجة اتنفّذت لسه

---

## 🎯 المبدأ الأساسي

**القاعدة:** كل حاجة حسّاسة على السيرفر محمية، والواجهة بتطلب توكن تلقائيًا.

**ليه ده مش بيزعج المستخدم؟**
الداتا فعلاً **بيتطلبها بعد الدخول** — `octa-core.js:555` بيقرأ `octa:authed`.
يعني الحجب مش هيضيف ولا خطوة — هو أصلاً بيشتغل صح.

---

## 🔴 المرحلة ١ — XSS أول (ساعتين)

**ليه الأول؟** لأنه بيخرب التوكن، فأي إصلاح بعده ممكن يتخرب تاني.

**١.** `esc()` في `octa-core.js` (نقل من `octa-app.js:32`)
**٢.** على ٤ مواضع:
`octa-core.js:1970` — `${n.link}`
`octa-core.js:1973` — `${n.title}`
`octa-core.js:2299` — `${n.link}`
`octa-core.js:2302` — `${n.title}`
**٣.** فحص كل `innerHTML` في `octa-core.js` — كل `${}` من مصدر خارجي

**اختبار:** جرب عنوان فيه `<script>alert(1)</script>` — لازم يظهر كنص.

---

## 🟠 المرحلة ٢ — البوابة (ساعة)

**٤.** `octa-gate.js:1935` — البوابة **تفضل مقفولة** لحد ما `/api/auth/me` يرجع ٢٠٠
**٥.** في حالة خطأ الشبكة: اعرض البوابة، مش الموقع
**٦.** شيل `overflow:hidden` من كل مسارات الخروج

**السلوك الجديد:**
```
توكن صالح   → 200 → ينفتح
توكن فاسد   → 401 → يطلع → البوابة
شبكة مقطوعة → error → البوابة (مش الموقع)
```

## 🟡 المرحلة ٣ — إخفاء الوصفة (٣٠ دق)

```
final_score, decision, technical_score, fund_score, liquidity_score,
risk_score_detailed, news_score, sentiment_score, opportunity_score,
```

لازم نعمل `/api/weights` محمي وتحدّث `octa-api.js` يطلبه بعد الدخول.
