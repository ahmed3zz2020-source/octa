# ⛔ تقرير حادث النشر + الحل النهائي (٩ نوفمبر ٢٠٢٦)

> **الخلاصة في سطر:** الأمر الافتراضي `npm run deploy` كان بينشر على **الإنتاج**
> لأن `wrangler` من غير `--config` بياخد `wrangler.jsonc` — واسمه `octa` = الإنتاج.
> **الحل النهائي:** `tools/deploy.sh` — المعاينة افتراضي، والإنتاج بعبارة صريحة
> + فحص بعد النشر + تراجع تلقائي.

---

## ① السبب الجذري (مش السبب الظاهر)

**السبب الظاهر:** «حصل deploy غلط».

**السبب الجذري:** الأمر اللي في التوثيق نفسه كان بينشر على الإنتاج:

```json
// package.json (قبل الإصلاح)
"deploy": "npm run build:strict && wrangler deploy"     // ⛔ بلا --config
```

```bash
# AGENTS.md (قبل الإصلاح) — "الأوامر المهمة"
npx --yes wrangler@4.151.1 deploy                        # ⛔ بلا --config ⇒ إنتاج
```

### ليه `wrangler deploy` من غير `--config` بيخطر؟

| الملف (قبل) | `name` | يعني |
|---|---|---|
| `wrangler.jsonc` | `octa` | 🔴 **الإنتاج** (octashares.com) |
| `wrangler-preview.jsonc` | `octa-preview` | 🟢 المعاينة |
| `wrangler-live.jsonc` | `octa` | 🔴 إنتاج (نسخة قديمة — اتشالت) |

`wrangler` بياخد `wrangler.jsonc` تلقائياً لما `--config` مش موجود.
⇒ **أي `npm run deploy` أو `wrangler deploy` من غير `--config` = نشر على الإنتاج.**

### ⭐ وبعدها (الإصلاح البنيوي): الافتراضي بقى **المعاينة**

| الملف (بعد) | `name` | يعني |
|---|---|---|
| `wrangler.jsonc` | `octa-preview` | 🟢 **الافتراضي — آمن** |
| `wrangler-prod.jsonc` | `octa` | 🔴 الإنتاج (لازم `--config` صريح) |

⇒ حتى لو حد نسي `--config` ⇒ بينشر على **المعاينة** مش الإنتاج.
(`wrangler-live.jsonc` اتشال — كان فخ تاني بنفس اسم الإنتاج.)

### الدليل (سجل Cloudflare الرسمي — `workers/scripts/octa/deployments`)

```

2026-11-09T22:42:26  wrangler   ← ٢
2026-11-09T22:42:28  wrangler   ← ٣
2026-11-09T22:42:30  wrangler   ← ٤

2026-11-09T22:43:26  api        (تغيير أسرار)
```

وفي المقابل — سجل `octa-preview`:

```

```

⇒ **٤ نشرات متتالية على الإنتاج في ٥٢ ثانية**، والمعاينة أول نشر لها بعدهم بـ **٢ دقيقة**.
الطلب كان «انشر المعاينة» ⇒ زي ما حصل.

## ③ الحل النهائي — `tools/deploy.sh`

### المعاينة (الافتراضي — آمن)

```bash
bash tools/deploy.sh preview
# أو:  npm run deploy
```

### الإنتاج (مستحيل من غير موافقة)

```bash
PUBLISH_PROD="ارفع على الدومين" bash tools/deploy.sh prod
# أو:  npm run deploy:prod
```

من غير العبارة ⇒ **يرفض ويقفل** (كود خروج 1):

```
╔══════════════════════════════════════════════════════╗
║  ⛔⛔⛔ رفض النشر على الإنتاج — من غير موافقة صريحة   ║
╚══════════════════════════════════════════════════════╝
   الهدف: الإنتاج (octashares.com)
   لو أحمد قال «ارفع على الدومين» ⇒:
     PUBLISH_PROD="ارفع على الدومين" bash tools/deploy.sh prod
```

### الحمايات الأربعة جوه السكربت

1. **🔒 قفل الإنتاج** — العبارة الصريحة مطلوبة (فوق).
2. **🎯 التحقق من الهدف** — السكربت بيقرأ `name` من ملف الإعداد ويقارنه بالهدف
   ⇒ لو الملف اتغيّر بالغلط ⇒ **يتوقف قبل النشر** (مش بعده).
3. **🔐 فحص الأسرار** — الإنتاج لازم ما يكونش فيه أسرار Halan
   (دي في `halan-feed` بس) ⇒ تسريب مستحيل.
4. **✅ فحص بعد النشر + تراجع تلقائي** — ٤ فحوصات حيّة
   (`/` · `/api/health` · `/api/rank` + الصفحة فيها سكريبت الموقع).
   لو فشل ⇒ `wrangler rollback` للإصدار **السابق بالاسم** (مش «الأحدث»،
   عشان ما نرجعش لإصدار قديم) ⇒ ⏱️ الأثر: ثواني بدل دقيقة.

> ⛔ **درس محفوظ:** `wrangler rollback` من غير `--yes` بيسأل أسئلة تفاعلية
> ⇒ في سكربت بيفشل ويترك العامل في حالة نص مكسورة. **لازم `--yes` دايماً.**

## ④ إصلاح تاني لقيته أثناء الشغل: كارت القرار مكانش بيظهر

### العَرَض
المودال `#mlay` موجود في الـDOM وفيه كل المحتوى،
بس `getBoundingClientRect()` = **0×0** ⇒ **الكارت مش بيظهر خالص**.

### السبب الجذري
`.mlay` كان **جوه `#page-markets`** ودي `.page` بـ `style="display:none"`:

```html
<div class="page" id="page-markets" style="display:none;">
  ...
  <div class="mlay" id="mlay">      <!-- ⛔ جوه صفحة مخفية -->
```

⇒ المودال `position:fixed` جوّه عنصر مخفي ⇒ **بياخد مقاس صفر**.

### الإصلاح
نقلنا `.mlay` لـ **child مباشر من `<body>`** ⇒ ظاهر من أي صفحة.

> ⭐ **القاعدة:** أي مودال (`position:fixed`) **لازم** يكون خارج أي `.page`.
> الـDOM موجود ≠ المستخدم شايف — اقيس `getBoundingClientRect()` قبل ما تسلّم.

## ⑤ محور الأخبار الحقيقي (هالان) — نفس يوم الإصلاح

### المشكلة

**١٨٢/١٨٢ مطابقة** (score + materiality + confidence + events + positives + negatives).

> ⛔ **الدرس:** وانتبه للترتيب! الباك بيحطّ أحداث BFD **الأول** وبعدين هالان،
> وبياخد **أول ١٠** أحداث وبيحسب الـmateriality من **أول** حدث.
> ⇒ لو رتّبنا بالتاريخ ⇒ الرقم هيتغيّر ⇒ لازم نفس الترتيب بالظبط.

## ⑦ القواعد اللي اتعلّمتها (قابلة للتعميم)

1. ⛔ **«الأمر الافتراضي» هو اللي بيحدد الخطر** — لو هو الخطر، غيّره.
   الحارس في سكربت جانبي = حارس مش موجود. **الحارس في المسار الافتراضي نفسه.**
2. ⛔ **العيب اللي في التوثيق بيتكرر** — الـREADME كان فيه الأمر الخطر.
3. ⛔ **راجع سجل الـcloud provider بعد كل حادث** — السجل هو الدليل
   (٤ نشرات في ٥٢ ثانية + أول نشر للمعاينة بعدهم بـ ٢ دقيقة = القصة كلها).
4. ⛔ **`wrangler rollback` من غير `--yes` بيسأل أسئلة** ⇒ في سكربت بيفشل ويترك
   العامل نص مكسور. **دايماً `--yes`.**
5. ⛔ **الـDOM موجود ≠ المستخدم شايف** — قِس `getBoundingClientRect()`.
   مودال `position:fixed` جوّه `.page` مخفي = **0×0**.
6. ⛔ **الترتيب جزء من المعادلة** — نفس المعادلة بترتيب مختلف = رقم مختلف.
7. ⛔ **«مفيش بيانات» مش رقم مخترع** — الـ45 قاعدة الباك نفسها،
   والصح هو **مصدر حقيقي** مش تغيير الرقم.
8. ⛔ **نسخة المحرك في مكانين = رقمين** ⇒ لازم **اختبار تطابق** بين النسختين.
